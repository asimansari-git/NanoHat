## 🎯 Objective & Problem Statement

### Problem
1. **Arbitrary Code Execution**: The legacy calculator tool used Python's `eval()`, exposing the OS host to arbitrary execution vulnerabilities.
2. **Missing CLI Usability**: Users could only interact with the agent via multi-turn scripts rather than running instant single-shot commands from the bash prompt (`nanohat <query>`).
3. **Unsafe Destructive Actions**: Non-interactive headless scripts could accidentally trigger file writes or deletions without confirmation.

### Accepted Solution
- **Safe AST Calculator (`runtime/tools.py`)**: Replaced `eval()` with `ast.parse`-based recursive evaluator restricting nodes to basic arithmetic and constants. See `[[ADR-001-AST-Calculator-Security]]`.
- **Fail-Closed Confirmation Gate (`runtime/tools.py`)**: Destructive actions fail closed in non-interactive mode unless explicitly overridden by `NANOHAT_AUTO_APPROVE_DESTRUCTIVE=1`. See `[[ADR-002-Fail-Closed-Confirmation-Gates]]`.
- **Packaging & Single-Shot Mode (`pyproject.toml`, `install.sh`, `runtime/agent.py`)**:
  - Exposed `nanohat` console script.
  - Enabled single-shot execution: `nanohat "<query>"` executes and exits immediately.
  - Added clean usage banner for empty invocations and `-i/--interactive` for chat.
- **Evaluation Harness (`eval/eval_harness.py`)**: Built automated benchmark suite for tool selection accuracy.
